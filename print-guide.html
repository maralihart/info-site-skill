The core loop

Ask → practice → check → adjust.

Choose one narrow outcome. Learn only the model needed to predict the first task. Complete a small example, compare the result with the expectation, then use that evidence to select the next step.

  • Name the audience and scope.
  • Use one consistent mental model.
  • Prefer observable checks over timing promises.
  • Qualify edition, model, region, and uncertainty.

Four actions

  1. Choose one outcome. Write a one-sentence goal with a result you can observe. Check: it contains only one main task.
  2. Map the minimum system. Name the parts, stages, states, or inputs controlling the result. Check: explain input → process → result.
  3. Try a complete small example. Use a safe, reversible task with no hidden prerequisite. Check: compare the result with a stated expectation.
  4. Diagnose and extend. Inspect from the start outward, change one variable, and retest. Check: explain the first mismatch and next experiment.

Do

  • Research before writing.
  • State date, version, model, region, and limits.
  • Put cautions beside affected steps.
  • Use labels and patterns—not color alone.
  • Keep web and print facts synchronized.

Avoid

  • Unsupported precision or guarantees.
  • Blending conflicting methods.
  • Related sources presented as exact.
  • New claims introduced only in print.
  • Type so small that a page count “fits.”

Quick diagnosis

Goal is too broad

Choose one smaller result with a visible finish.

Result differs

Check version, environment, tools, and starting state first.

Copying without understanding

Ask which input changed and which stage should respond.

Sources conflict

Compare context and dates; record uncertainty and qualify wording.

High-stakes boundary

For health, safety, legal, financial, or equipment-risk instructions, rely on current authoritative guidance, state the limits of this guide, repeat critical cautions here, and provide clear escalation steps.
